# How LINQ Works Internally

## Overview

When you write a LINQ query, .NET does **not execute it magically**.

Internally, LINQ works using:

1. Extension Methods
2. Lambda Expressions
3. Delegates
4. IEnumerable / IQueryable
5. Iterators (yield return)
6. Deferred Execution
7. Expression Trees (for databases)

---

## Step 1: Query Syntax is Converted to Method Syntax

When you write:

```csharp
var result =
    from e in employees
    where e.Salary > 50000
    select e;
```

The C# compiler converts it into:

```csharp
var result =
    employees.Where(e => e.Salary > 50000);
```

### Important Interview Point

**Query Syntax is only syntactic sugar.**

Internally, the compiler translates query syntax into method syntax.

---

## Step 2: Extension Methods are Called

Methods like:

```csharp
Where()
Select()
OrderBy()
GroupBy()
```

are actually **extension methods**.

Example:

```csharp
employees.Where(e => e.Salary > 50000);
```

Internally:

```csharp
Enumerable.Where(
    employees,
    e => e.Salary > 50000
);
```

Where method belongs to:

```csharp
System.Linq.Enumerable
```

---

## Step 3: Lambda Expression Becomes Delegate

When you write:

```csharp
e => e.Salary > 50000
```

Compiler converts it into a delegate.

Equivalent:

```csharp
bool CheckSalary(Employee e)
{
    return e.Salary > 50000;
}
```

And internally:

```csharp
Func<Employee, bool> predicate = CheckSalary;
```

---

## Step 4: IEnumerable Takes Control

Consider:

```csharp
var result =
    employees.Where(e => e.Salary > 50000);
```

The return type is:

```csharp
IEnumerable<Employee>
```

Meaning:

> "I know how to produce employees one by one when requested."

No data is retrieved yet.

---

## Step 5: Deferred Execution

This is the most important concept.

When you write:

```csharp
var result =
    employees.Where(e => e.Salary > 50000);
```

### What happens?

Nothing executes yet.

LINQ only stores:

* Source collection
* Filtering condition

Execution starts only when:

```csharp
foreach(var emp in result)
{
    Console.WriteLine(emp.Name);
}
```

---

## Visual Flow

```text
Write Query
     ↓
Create Query Object
     ↓
Store Conditions
     ↓
No Execution Yet
     ↓
foreach / ToList()
     ↓
Execute Query
```

---

## Step 6: Iterator Pattern

Internally LINQ uses iterators.

Simplified version:

```csharp
public static IEnumerable<T>
Where<T>(
    IEnumerable<T> source,
    Func<T,bool> predicate)
{
    foreach(var item in source)
    {
        if(predicate(item))
        {
            yield return item;
        }
    }
}
```

### Important

```csharp
yield return
```

allows elements to be generated one at a time.

Benefits:

* Less memory usage
* Faster execution
* Lazy evaluation

---

## Step 7: Deferred vs Immediate Execution

### Deferred Execution

```csharp
var result =
    employees.Where(e => e.Salary > 50000);
```

No execution.

---

### Immediate Execution

```csharp
var result =
    employees.Where(e => e.Salary > 50000)
             .ToList();
```

Execution happens immediately.

Why?

Because:

```csharp
ToList()
ToArray()
Count()
First()
Single()
```

need actual data.

---

## Internal Flow of Where()

Example:

```csharp
var result =
    employees.Where(e => e.Salary > 50000);
```

Internally:

```text
employees
    ↓
Enumerable.Where()
    ↓
Store Predicate
    ↓
Return IEnumerable
    ↓
foreach starts
    ↓
Read Employee 1
    ↓
Check Condition
    ↓
Yield if True
    ↓
Read Employee 2
    ↓
Check Condition
    ↓
Yield if True
```

---

## How Multiple LINQ Operations Work

Example:

```csharp
var result =
    employees
        .Where(e => e.Salary > 50000)
        .OrderBy(e => e.Name)
        .Select(e => e.Name);
```

Internally:

```text
Source Collection
      ↓
Where Filter
      ↓
OrderBy Sort
      ↓
Select Projection
      ↓
Result
```

Execution starts only when enumerated.

---

## LINQ to Objects vs LINQ to SQL

### LINQ to Objects

```csharp
employees.Where(e => e.Salary > 50000);
```

Works on:

```csharp
IEnumerable<T>
```

Execution happens in memory.

---

### LINQ to SQL / Entity Framework

```csharp
db.Employees.Where(e => e.Salary > 50000);
```

Works on:

```csharp
IQueryable<T>
```

Here LINQ creates an **Expression Tree** instead of a delegate.

---

## Expression Tree

For:

```csharp
e => e.Salary > 50000
```

LINQ builds a tree representation:

```text
GreaterThan
    /     \
Salary   50000
```

Entity Framework reads this tree and converts it into SQL:

```sql
SELECT *
FROM Employees
WHERE Salary > 50000
```

---

## Difference Between IEnumerable and IQueryable

| Feature     | IEnumerable        | IQueryable           |
| ----------- | ------------------ | -------------------- |
| Works On    | Collections        | Databases            |
| Execution   | In Memory          | Database             |
| Uses        | Delegates          | Expression Trees     |
| Namespace   | System.Collections | System.Linq          |
| Performance | Good for Objects   | Better for Databases |

---

## Complete Internal LINQ Flow

```text
LINQ Query
     ↓
Compiler Converts Query Syntax
     ↓
Method Syntax
     ↓
Extension Methods Called
     ↓
Lambda → Delegate/Expression Tree
     ↓
IEnumerable/IQueryable Created
     ↓
Conditions Stored
     ↓
Deferred Execution
     ↓
foreach / ToList()
     ↓
Actual Execution
     ↓
Results Returned
```
